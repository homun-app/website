Engramma 0.6.19-beta.1 — the capture behind the Engramma docs
================================================================

Every command and output quoted by the pages under /docs/engramma/ comes
from this session: the released binary (commit 5d0e02a), installed by the
release installer into a temporary folder, on a fresh data root
(ENGRAMMA_ROOT and ENGRAMMA_MODEL_DIR inside <tmp>), with the synthetic
notes of the site (Gaia, Milano, Torino, Acme). The CLI prints in English
since 0.6.19: output is verbatim; what was changed: paths are shortened
(<tmp> is the temporary folder of the session) and the capture script's own
bookkeeping lines are left out.

The proposing client of S5b and S12 is a stdio MCP driver carrying the
configuration Claude Code would carry (`--actor claude-code`, so the engine
signs `mcp:claude-code`): the engine side is real, the client side is the
driver (`declared client: site-capture-driver 0.0.1`). The model was pulled
into <tmp>/models before this session (the session behind the page shows the
pull, S16); S3 pulls again, and the binary answers that it is already there.

The notes are the synthetic notes of the site, in Italian. Two bodies —
Ufficio a Torino, CFO di Acme — were written again for this capture, as in
the session behind the page (its header says why); so was the text of the
second proposal of S12, of which the 0.6.17 capture printed the title alone.
S7 edits the Gaia file in the vault before `vault sync`, so that the report
shows the folder telling the cell: on a vault just initialized the sync
answers `nothing to do`. The 0.6.17 capture showed that report without
showing the edit.

The defect the 0.6.17 capture declared is closed since 0.6.18: `engramma
revert <id> --dry-run` reverted for real. S5c shows the dry run writing
nothing (`verify` counts the same operations before and after) and the real
revert after it.
