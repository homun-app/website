Engramma 0.6.17-beta.1 — the capture behind the Engramma page
=============================================================

The terminal lines, the log rows and the figures of /engramma/ come from this
session: the released binary (commit 1bfc611), installed by the release
installer into a temporary folder, on a fresh data root, with the synthetic
notes of the page (Gaia, Milano, Torino, Acme). Commands and output are
verbatim. What was changed: paths are shortened (<tmp> is the temporary folder
of the session, <node> the node executable), a JSON dump of the queue and a
few lines of the capture script's own failures are left out.

  S0    the binary and an empty memory
  S1    the synthetic notes
  S2    hero: a search that explains itself, then verify
  S3    meaning: the same question in other words, in another language
  S4    time: what is true today, and what was true in August
  S5    control: a claim from a web page waits outside the results
  S6    hub, story 1: Claude Code proposes, you accept, a second client reads
  S7    hub, story 2: Cursor proposes, the reviewer decides, OpenCode reads
  S8    hub, story 3: ChatGPT proposes something it read on a web page
  S9    the limit of confidence
  S10   revert --by: whose decisions a bulk revert undoes (dry runs)
  S11   two tools correct the same note: both accepted, no conflict copy
  S11b  … then a real revert, and you keep one of the two (S14)
  S12   the accepted proposals have no vector until `embed` runs
  S13   what a reader gets in each story
  S15   the graph path the engine prints

The clients of the session
--------------------------
Story 1 is real end to end: Claude Code 2.1.332 proposed through its own MCP
client (--mcp-config, headless) and the MCP Inspector 2.16.0 read the same
cell. Codex was not installed on the machine, so the other actors — Cursor,
OpenCode, ChatGPT, Homun, and Codex as the reader of story 1 — were a stdio
MCP driver carrying the configuration each client would carry.
On the day of the docs (S16, at the end of this file) the story was run a
second time with Codex as the reader: the Codex CLI of the Codex app searched
through its own MCP client and found the note Claude Code had proposed. The engine
signs the actor of the configuration, never what the client says it is, so
the engine side of those scenes is the real one; the client side is not.
The reviewer `local` is a fixture that answers with a fixed rule (accept what
the user stated with confidence 0.9, escalate the rest), not a model.

What the session showed, beyond the page
----------------------------------------
- `revert --by mcp:<actor>` is accepted and undoes nothing: decisions are
  signed by who decided (user@cli, reviewer:<name>), never by who proposed.
- A read leaves no trace in the log: `verify` counts the same operations
  before and after a search, by CLI and by MCP.
- Two accepted corrections of the same note become two active notes;
  `conflicts` reports no copy. Conflict copies come from two devices.
- A proposal that was accepted has no vector until `engramma embed` runs
  (`copertura vettori: 8/14 note`), so a question with no word in common does
  not find it before that.
