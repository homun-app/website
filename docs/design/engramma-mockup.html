    Not a database. A memory with a method.

    One file per memory space on your disk, and inside it five stages that turn what an assistant learns into answers you can check.

    How truth is kept

    Many tools write. One history decides.

    When several assistants share a memory, the hard part is not storing facts: it is knowing which ones to believe. Engramma answers with rules, not with whoever wrote last.

    1. The log is the truthNotes, graph and indexes are derived from one hash-chained log. engramma verify rebuilds them and must find the same state.
    2. Every fact is signedWho wrote it (you, mcp:codex, a reviewer), from which source, with what confidence, valid from when.
    3. Your policy is the gatePer memory space: proposals wait for you, or a reviewer model decides within your limits — confidence, note types, a cap per hour.
    4. Disagreements stay visibleTwo writes to the same note that did not see each other — two devices, or two tools’ accepted proposals — make a conflict copy, closed only by a decision. Never last-write-wins.
    5. Change keeps historyA new fact supersedes the old one with dates; ask what was true on any day.
    6. Mistakes undo in one moveRevert everything one tool or reviewer did since Tuesday, with a preview. Purge forgets for real.

    Connect

    Your memory in the assistant you use.

    $ claude mcp add engramma -- ~/.cargo/bin/engramma \
    mcp --cells work --write work --actor claude-code

    Local apps start Engramma on your computer over stdio.

    Web and mobile apps reach it over HTTPS with OAuth 2.1, through a tunnel you choose.

    Only the spaces you name are exposed. Assistants can search and propose — never confirm, delete or change a rule.

    Questions

    Asked before you install.

    Does it replace a RAG stack?

    For your notes and conversations, yes: it chunks, embeds and searches them by words, meaning and graph in one file, with no vector database and no embedding API — and says why each result matched. Point it at a Markdown folder or an Obsidian vault with engramma import. PDF, Office files and web pages are not ingested yet: they are on the roadmap.

    Can several tools use the same memory at once?

    Yes. Each connects with its own name; reads are shared, writes are proposals signed by that tool and handled by the memory space’s policy.

    Does it need an API key or a GPU?

    No. The embedding model runs on the CPU inside the engine. A remote embedding endpoint is optional.

    Where is my data?

    In one file per memory space on your disk. Sync between your devices is end-to-end encrypted; a relay can forward it but never read it.

    How does it relate to Homun?

    Engramma is Homun’s memory. The same engine ships as a command line and an MCP server for any assistant.

    Will my memory survive updates?

    Yes: every later version opens memory written by this one. The promise and its tests are in the repository.
